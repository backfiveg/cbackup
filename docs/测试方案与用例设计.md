## 1. 测试策略概述

### 1.1 测试方法体系

本项目采用**四层**测试方法体系，确保从微观到宏观全面覆盖：

| 测试层次 | 测试方法 | 测试工具 | 覆盖目标 | 测试用例数 |
|----------|----------|----------|----------|-----------|
| **单元测试** | 白盒 + 黑盒 | gtest | 语句/分支/条件/边界覆盖 | 96 (已实现) |
| **集成测试** | 自底向上 | Shell + gtest | 模块间接口与数据流 | 16 (见下文) |
| **性能测试** | 基准测试 | gprof / time / perf | I/O 吞吐、压缩率、加密速度 | 6 (见下文) |
| **稳定性测试** | 压力测试 | valgrind / fault injection | 内存泄漏、异常恢复、极限输入 | 8 (见下文) |

### 1.2 白盒测试覆盖准则

针对 CLI 解析模块的白盒测试，遵循以下覆盖准则：

- **语句覆盖 (C0)**: 100% — `parse_args()` 的每一条可执行语句至少执行一次
- **分支覆盖 (C1)**: 100% — 每个 `if/else`、`switch/case` 的取真/取假分支均覆盖
- **条件覆盖 (C2)**: 100% — `--owner` vs `--user` 别名、`-z` vs `--compress` 简写等复合条件
- **边界值分析**: 空输入、单参数、重复参数、缺失参数、大数值

```bash

docker run --rm --entrypoint bash cbackup -c "cd /workspace/build && ctest --output-on-failure"
```

## 3. 模块一：CLI 参数解析 — 白盒单元测试

### 3.1 测试策略

**测试方法**：白盒单元测试 (gtest)
**测试文件**：`tests/test_cli_parser.cpp`
**覆盖技术**：语句覆盖 (C0) + 分支覆盖 (C1) + 条件覆盖 (C2) + 边界值分析
**测试用例数**：40（已实现）

### 3.2 被测代码分析

```cpp
// 核心函数签名
bool parse_args(int argc, char* argv[], CliArgs& out);
void print_usage(const char* prog);
```

**控制流图关键节点**：
1. `argc < 2` → 打印用法，返回 false
2. `subcmd` 字符串匹配 (6 路分支: backup/restore/pack/unpack/daemon/cron/unknown)
3. 选项解析循环 (20+ 种选项，每种的 `next_arg` 可能返回 nullptr)
4. 必填参数验证 (6 种子命令各需不同参数组合)

### 6.2 测试步骤（TC-EX02-01 详细）

```bash
# 步骤1: 创建带特定时间戳的文件
echo "stamped" > /tmp/ex02_src/stamp.txt
touch -t 202401010101.30 /tmp/ex02_src/stamp.txt

# 步骤2: 记录原始元数据

# 步骤4: 还原

# 步骤5: 验证时间戳 (精确到秒)
```

## 附录 B：gtest 断言使用说明

| 断言宏 | 用途 | 示例 |
|--------|------|------|
| `ASSERT_TRUE(cond)` | 致命断言, 失败则终止当前测试 | `ASSERT_TRUE(parse_args(...))` |
| `EXPECT_TRUE(cond)` | 非致命断言, 失败继续执行 | `EXPECT_TRUE(args.compress)` |
| `ASSERT_EQ(a, b)` | 相等断言 (致命) | `ASSERT_EQ(args.source, "/src")` |
| `EXPECT_EQ(a, b)` | 相等断言 (非致命) | `EXPECT_EQ(args.keep, 5)` |
| `EXPECT_THROW(stmt, ex)` | 断言抛出指定异常 | `EXPECT_THROW(func(), std::runtime_error)` |
| `EXPECT_NO_THROW(stmt)` | 断言不抛出异常 | `EXPECT_NO_THROW(print_usage("cbackup"))` |
| `EXPECT_NEAR(a, b, tol)` | 浮点/时间容差比较 | `EXPECT_NEAR(epoch, target, 5.0)` |
