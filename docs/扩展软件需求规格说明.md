数据备份软件需求分析说明书

1. 引言

1.1 编写目的

本文档旨在明确《数据备份软件》的系统需求与规格边界，为最多由3名开发人员组成的研发团队提供清晰、无歧义的技术蓝图。本文档将作为后续系统架构设计、接口定义、代码编写以及基于 gtest 测试用例编写的唯一基准。

1.2 项目背景

本项目为《软件开发综合实验》的核心实战任务，要求团队经历从需求分析到最终交付的完整软件生命周期。系统聚焦于文件系统级的数据备份与恢复，重点考核软件的正确性、易用性、健壮性以及 Linux 环境下的系统级 C++ 编程能力。为追求极致的工程挑战与展示效果，本项目在核心功能之上，引入了算法深度的考察（自研算法）以及现代 Web 图形界面的全栈开发。

1.3 受众说明

本文档的预期读者包括：开发团队成员、项目导师、负责最终验收与代码审查的助教及评审委员会。

2. 总体描述

2.1 用户特点

目标用户群体主要为具备一定计算机基础的系统管理员、开发者或高级用户。用户既可以通过高效的命令行（CLI）进行自动化脚本集成，也可以通过直观的图形界面（GUI）进行可视化的任务配置与状态监控。

2.2 运行环境说明

宿主环境：Windows 操作系统（浏览器访问图形界面）。

目标与交付环境：基于 Docker 构建的标准化 Linux 容器。最终项目交付物必须包含完整的 Dockerfile，确保环境的一致性与可复现性。容器需对外暴露 Web 服务端口（如 8080）。

交互接口：系统采用“双引擎”交互——底层提供纯命令行接口 (CLI)，上层提供基于 Web B/S 架构的图形界面 (GUI)。

2.3 设计与工具链约束

语言约束：核心后台数据处理逻辑必须 100% 采用 C++ 编写。Web GUI 的胶水层服务器允许使用 Python（如 Flask/FastAPI），前端采用 HTML/JS/CSS（如 Tailwind CSS）。

工具链：开发与调试依托于 VSCode 远程容器开发模式。构建系统强制使用 CMake 与 Make。代码版本控制采用 git。

第三方依赖：C++ 核心需链接 zlib (用于辅助压缩功能) 和 openssl (用于辅助加密功能)。

质量保障：

代码规范需通过 cpplint 检查。

单元测试需基于 gtest 框架覆盖核心逻辑。

内存泄漏与越界访问需使用 valgrind 进行严格排查。

性能瓶颈分析需借助 gprof 或 perf。

3. 核心功能用例分析

本章节定义系统的基础能力（对应基础评估 40 分）。

3.1 用例：目录树数据备份

前置条件：源目录存在且当前用户具有读权限；目标路径所在的父目录存在且当前用户具有写权限。

输入：源目录的绝对或相对路径；目标存储路径。

处理逻辑：

系统解析输入路径，校验路径合法性。

采用深度优先 (DFS) 或广度优先 (BFS) 算法递归遍历源目录树。

逐一读取源文件数据，并在目标路径下按原有层级结构创建对应目录与文件。

将数据流完整写入目标文件。

输出：终端或 GUI 控制台打印备份进度（如文件数量/字节数）及最终成功/失败状态码。

3.2 用例：目录树数据还原

前置条件：指定的备份源数据（目录或打包文件）存在且未损坏；目标恢复路径合法且具备写权限。

输入：备份数据所在的路径；期望恢复到的目标目录路径。

处理逻辑：

系统校验备份数据的完整性与合法性。

解析备份结构，在目标路径下逆向重构目录树。

将备份的数据内容准确写入到重构出的文件树中。

输出：控制台打印恢复操作的执行报告，包括恢复的文件总数与最终状态。

4. 扩展功能规格详解

为达成满分目标，系统将在 Linux C++ 底层实现以下高级特性，并结合前端技术呈现。

4.1 特殊文件支持 (EX-01) - 10分

功能描述：在遍历目录时，系统需正确识别并持久化特殊文件的拓扑与属性，而非盲目读取其内容。

技术表现：通过 Linux lstat() 系统调用读取文件状态，利用宏（如 S_ISFIFO, S_ISLNK, S_ISCHR, S_ISBLK）进行精准分支处理。

4.2 元数据支持 (EX-02) - 10分

功能描述：实现“原样备份”，确保文件恢复后的属主、时间戳及读写执行权限与原文件完全一致。

技术表现：依托 stat 结构体，提取相关元数据。恢复阶段调用 chown()、chmod() 以及 utimensat() 以纳秒级精度恢复访问与修改时间。

4.3 自定义备份全维度支持 (EX-03) - 18分 (3分 x 6项)

功能描述：在目录树遍历过程中挂载强大的过滤器链，支持 6 个维度的自定义组合筛选。

技术表现：在 lstat 获取文件元数据后，将 struct stat 传入过滤器进行综合研判。

按路径 (Path)：排除特定目录（如 .git/）。

按类型 (Type)：精确控制是否备份普通文件、符号链接或特殊设备。

按名称 (Name)：基于 <regex> 支持通配符匹配（如 *.cpp）。

按时间 (Time)：通过读取 st_mtime，支持按绝对时间或相对天数过滤。

按尺寸 (Size)：通过 st_size 过滤大于/小于特定 Byte 数值的文件。

按用户 (User)：利用 getpwnam() 将用户名解析为 UID，与 st_uid 比对。

4.4 打包与解包 (EX-04) - 10分

功能描述：消除碎文件带来的 I/O 开销与管理困难，将整个目录树序列化为单一二进制大文件。

技术表现：设计自定义的二进制封包协议，包含全局魔数、文件条目元数据头与连续数据块。

4.5 压缩与解压多算法支持 (EX-05) - 15分

功能描述：在二进制打包协议之上引入压缩模块。

技术表现：支持全手工实现的 Huffman 算法 (10分)，以及调用第三方库的 Zlib 算法 (5分)。通过工厂模式在运行时根据参数动态切换压缩引擎。

4.6 加密与解密多算法支持 (EX-06) - 15分

功能描述：由用户输入密钥，对文件内容进行全量加密处理。

技术表现：

自研 RC4 流密码 (10分)：全手工实现。根据密钥初始化 256 字节 S-Box (KSA 算法)，生成密钥流 (PRGA) 与数据流进行高速 XOR 异或加密。

集成 AES-128 对称加密 (5分)：调用 <openssl/evp.h> 中的高级加密标准，使用 CBC 模式处理块对齐。

4.7 定时备份与淘汰机制 (EX-07) - 10分

功能描述：后台周期性自动备份，并防磁盘占满。

4.8 实时增量备份 (EX-08) - 15分

功能描述：利用 Linux inotify 机制感知文件变化，触发低延迟增量同步。

4.9 现代化图形界面 (GUI) (EX-09) - 10分

功能描述：实现一个友好、直观的 Web 图形界面，供用户配置所有的自定义备份条件、选择算法组合，并实时监控底层 C++ 引擎的执行日志。

技术表现：

采用 B/S 架构。Docker 容器内部署轻量级 Python Flask Web 服务器。

前端采用现代响应式框架（如 Tailwind CSS + 原生 JS/Vue），界面设计遵循“极客控制台”风格。

Flask 路由通过 subprocess.Popen 调用 C++ cbackup 可执行文件，并将 stdout/stderr 标准输出通过 Server-Sent Events (SSE) 或轮询流式返回前端，实现“黑色终端模拟器”的实时打印效果。

5. 非功能需求

5.1 内存安全与资源管理

零泄漏承诺：系统必须通过 valgrind --leak-check=full 测试。特别是OpenSSL 上下文 (EVP_CIPHER_CTX) 的申请与释放必须使用智能指针配合自定义 Deleter 做到万无一失。

5.2 性能指标

I/O 优化：流式加解密（尤其是 AES）与压缩必须以 Chunk（如 64KB）为单位在内存中分块进行，避免将 GB 级大文件一次性读入内存导致 OOM。

6. 交互接口规范

6.1 命令行 (CLI) 接口

主命令为 cbackup，完全支持链式参数配置。

# 执行打包+AES加密+过滤配置的终极命令
cbackup pack --compress huffman --encrypt aes -p "secret123" \
    --mtime "-7d" --size "<500M" --owner root \
    --source /data/src --dest /data/archive.cbk


6.2 Web GUI 接口

访问方式：宿主机浏览器访问 http://localhost:<映射端口>

核心模块：任务控制大盘 (Dashboard)、可视化参数表单、实时 C++ 执行终端监控窗。
