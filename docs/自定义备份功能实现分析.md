# 自定义备份功能实现分析

## 概述

自定义备份通常涉及 6 个维度的过滤条件：**名字、路径、类型、时间、尺寸、用户**。本文档逐维分析 cbackup 当前代码中每个维度的实现状态，标注已实现与缺失部分，并给出改进突破口。

---

## 关键代码瓶颈

backup 和 pack 的文件过滤发生在同一个位置：

**backup.cpp:209-221** / **packer.cpp:146-156**：
```cpp
struct stat st;
if (lstat(src_path.c_str(), &st) != 0) {
    Logger::warn("lstat failed: " + src_path);
    stats.files_skipped++;
    continue;
}

// ╔══════════════════════════════════════════════════════════╗
// ║  ⚠️ 瓶颈所在: filter 只接收 rel_path, 不接收 struct stat ║
// ╚══════════════════════════════════════════════════════════╝
if (!S_ISDIR(st.st_mode) && !filter.should_include(rel_path)) {
    Logger::info("Filtered out: " + rel_path);
    stats.files_skipped++;
    continue;
}
```

`struct stat` 已通过 `lstat()` 获取了文件的所有元数据：

| struct stat 字段 | 含义 | 当前用途 | 是否用于过滤 |
|------------------|------|----------|:---:|
| `st_mode` | 文件类型+权限 | `S_ISDIR/REG/LNK/FIFO/CHR/BLK` 类型判断 | ⚠️ 仅类型分支 |
| `st_size` | 文件大小(字节) | 累加 `stats.bytes_copied` | ❌ |
| `st_mtime` / `st_atime` | 修改/访问时间 | `-m` 时用 `utimensat` 保留 | ❌ |
| `st_uid` / `st_gid` | 所有者/组 | `-m` 时用 `fchown` 保留 | ❌ |
| `st_dev` / `st_ino` | 设备+inode | pack 硬链接去重 | ❌ |

**根本原因**：`Filter::should_include()` 的签名只接受路径字符串：

```cpp
// filter.h:18 — 当前签名
bool should_include(const std::string& rel_path) const;
//                                     ^^^^^^^^^
//                         只接受路径，元数据被丢弃
```

所有 struct stat 数据虽然在调用处已就绪，但从未传入过滤器。

### 1. 名字 (Name) — 按文件名模式过滤

| 项目 | 内容 |
|------|------|
| **实现状态** | ✅ **已完整实现** |
| **完成度** | 100% |
| **涉及文件** | `filter.cpp:6-59`, `filter.h`, `cli_parser.cpp:127-132` |

**实现原理**：

```
用户输入: --include "*.cpp" --exclude "test_*"
    │
    ▼
cli_parser.cpp:128-132 → 存入 FilterConfig::include_patterns / exclude_patterns
    │
    ▼
filter.cpp:30-34  → Filter 构造函数
    ├── glob → regex: "*.cpp" → "^.*\.cpp$"
    └── 编译为 std::regex
    │
    ▼
filter.cpp:37-59  → Filter::should_include(rel_path)
    ├── 提取文件名: rel_path.rfind('/') → filename
    ├── exclude 优先: regex_match(filename) || regex_match(full_path) → false
    ├── include 检查: 同上 → true
    └── 无 include 列表: 默认通过
```

**CLI 用法**：
```bash
cbackup backup --source /src --dest /dst \
    --include "*.cpp" \          # 只备份 C++ 源文件
    --include "*.h" \            # 和头文件
    --exclude "test_*" \         # 排除测试文件
    --exclude "build/*"          # 排除整个 build 目录
```

**支持的 glob 语法** (`filter.cpp:6-28`)：

| glob | 转换后的 regex | 匹配示例 |
|------|---------------|----------|
| `*` | `.*` | `hello.txt` ← `*.txt` |
| `?` | `.` | `a.txt` ← `?.txt` |
| `[abc]` | `\[abc\]` (转义) | 当前不支持字符类 |
| `/` | `/` (原样) | 路径分隔符 |

**覆盖范围**：单个文件名模式 ✅ | 目录路径模式 ✅ | 多模式组合 ✅

### 3. 类型 (Type) — 按文件类型过滤

| 项目 | 内容 |
|------|------|
| **实现状态** | ⚠️ **部分实现** |
| **完成度** | ~35% |
| **涉及文件** | `backup.cpp:83-149`, `packer.cpp:39-47`, `packer.h:14-22` |

**已实现**：

`classify()` 函数能精确区分的 6 种类型（`packer.cpp:39-47`）：

```cpp
static EntryType classify(const struct stat& st) {
    if (S_ISREG(st.st_mode))  return EntryType::REGULAR;    // 普通文件
    if (S_ISDIR(st.st_mode))  return EntryType::DIRECTORY;  // 目录
    if (S_ISLNK(st.st_mode))  return EntryType::SYMLINK;    // 符号链接
    if (S_ISFIFO(st.st_mode)) return EntryType::FIFO;       // 命名管道
    if (S_ISCHR(st.st_mode))  return EntryType::CHR_DEV;    // 字符设备
    if (S_ISBLK(st.st_mode))  return EntryType::BLK_DEV;    // 块设备
    return EntryType::REGULAR;
}
```

CLI 控制：`special_files` 布尔开关（`BackupOptions.special_files`）

**未实现**：

| 缺失功能 | 说明 |
|----------|------|
| 精细类型选择 | `special_files` 是全局开关，要么全备份要么全跳过 |
| 单独控制 | 无法"只要普通文件+符号链接，不要 FIFO 和设备文件" |
| CLI 类型参数 | 无 `--type` 或 `--file-type` 选项 |

**当前的分支逻辑问题**（`backup.cpp:232-253`）：

```cpp
} else if (S_ISLNK(st.st_mode) && opts.special_files) {     // ⚠️ 全开或全关
    backup_symlink(...);
} else if (S_ISFIFO(st.st_mode) && opts.special_files) {    // ⚠️ 同上
    backup_fifo(...);
} else if ((S_ISCHR || S_ISBLK) && opts.special_files) {    // ⚠️ 同上
    backup_device(...);
}
```

——每个特殊类型都绑定到同一个 `opts.special_files` 布尔值，缺乏独立控制。

**覆盖范围**：6 种类型识别 ✅ | 全局开关 ✅ | 精细类型选择 ❌ | 类型组合 ❌

```cpp
uid_t resolve_user(const std::string& name) {
    struct passwd* pw = getpwnam(name.c_str());

    return pw->pw_uid;
}
```

## 实现突破口

所有 4 个未实现维度（时间/尺寸/用户/类型精细控制）的瓶颈完全相同：

### 当前架构

```
lstat(path) → struct stat st  ─┬→ 类型分支 (S_ISREG/DIR/LNK...)
                               ├→ bytes_copied 统计
                               ├→ -m 元数据保留 (fchown/utimensat)
                               └→ ⚠️ 丢弃! (未传给 filter)
                               
filter.should_include(rel_path)  ← 只看到路径字符串
```

### 目标架构

```
lstat(path) → struct stat st  ─┬→ 类型分支
                               ├→ 统计
                               ├→ -m 元数据保留
                               └→ filter.should_include(rel_path, st) ✅
                                    ↓
                               根据 名字 + 时间 + 尺寸 + 用户 + 类型 综合判断
```
